# ANSWER_SCRIPT：答辩讲稿简版

## 1. 项目介绍

我们做的是序号 21，多模型协作翻译与审校系统。它的核心目标不是只做翻译，而是让两个模型翻译同一段文本，再用可复现规则打分，最后推荐最佳译文并给出修改建议。

## 2. 核心流程

流程是：输入文本 → 复杂度评估 → 路由决策 → 两个模型翻译 → 规则评分 → 审校子 Agent → 推荐译文。

## 3. 自主实现的部分

主要有三个：

1. 复杂度评估是自己写的，统计平均句长、嵌套从句数和术语密度。
2. 评分模型是自己写的，有 8 条扣分规则，例如数字遗漏每处扣 8 分、术语不一致每处扣 6 分。
3. 中间件是自己写的，统计模型调用耗时、token 和估算成本。

## 4. 为什么这样设计

不能直接让 LLM 判断“哪个译文好”，因为这样不可复现，答辩时也说不清为什么扣分。所以我们把质量评估拆成明确规则，让 LLM 只负责语言生成，规则引擎负责确定性评分。

## 5. 演示点

1. 文本翻译：展示两个模型译文和评分表。
2. 专业文本：展示术语命中和术语一致性扣分。
3. Benchmark：展示 10 段不同领域文本的评分与耗时。
4. Markdown：展示保持目录结构。
5. OCR：展示图片文字提取后翻译。

## 6. 可回答的问题

### 问：复杂度怎么计算？

答：总分由句长分、从句分、术语密度分组成。句长按平均 token 数分档，从句用 which、because、although 等规则词和标点估计，术语密度由术语表命中数除以 token 数得到。

### 问：为什么不让 LLM 直接评分？

答：课题要求确定性逻辑自主实现，可复现。LLM 直接评分每次可能不一样，所以我们用规则扣分。

### 问：模型路由有什么用？

答：路由根据复杂度决定提示词强度。低复杂度快速双译，中高复杂度强制术语表并启用审校。为了满足两个模型对比，演示时两个模型都会调用。

### 问：系统有什么不足？

答：规则评分只能发现显性问题，比如数字、术语、长度和结构；对于很细腻的语义误差仍需要人工复核。后续可以加入人工标注数据优化规则权重。
