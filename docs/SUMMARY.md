- 实现双模型翻译接口。

- 实现模型调用耗时与成本统计中间件。

## 2. 遇到的问题

### 问题 1：不能让 LLM 直接给最终分

如果直接问 LLM“这个译文多少分”，结果不可复现，答辩时也说不清为什么扣分。

解决办法：把评分拆成明确规则，例如数字遗漏扣 8 分、术语不一致扣 6 分。LLM 只负责生成译文和语言建议。

### 问题 2：复杂度评估不能依赖模型判断

课题要求“自主实现”，所以不能让 LLM 判断文本难不难。

解决办法：用规则统计平均句长、从句标记、术语密度，形成可复现分数。

### 问题 3：没有 API Key 时项目无法演示

如果答辩现场网络或 Key 出问题，项目可能跑不起来。

解决办法：加入 `MOCK_MODE`，即使没有模型也能演示完整流程。真实模型可通过 `.env` 切换。

### 问题 4：Markdown 文档容易破坏结构

直接整篇翻译可能破坏标题、列表、代码块。

解决办法：逐行处理 Markdown，标题只翻译标题内容，代码块保持不变，列表保留前缀。

## 3. 如果再做一次会改进什么

1. 增加更大的术语库，并按领域自动选择术语表。
2. 引入真实人工标注译文，评估规则分与人工分的一致性。
3. 加入更多语言方向，例如中译英、日译中。
4. 把审校 Agent 改成可调用外部工具的 LangGraph 子 Agent。
5. 增加翻译记忆库，重复句子直接复用历史最佳译文。
6. 对 OCR 增加版面分析，支持保留表格和段落位置。

## 4. 后续扩展方向

- 支持术语冲突检测。
- 支持人工选择某个译文后反向优化评分权重。
- 支持团队协作审校流程。
